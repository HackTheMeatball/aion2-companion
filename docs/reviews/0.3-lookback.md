## What was slow

1. **Opening PRs by hand** for 14 issues (fixed by #125: bots open their own).
2. **Long test runs inside a bot job:** golden, pixel and journey runs ended jobs (#96, #101) or had to be split by hand
   (#108 ran the suites in two halves). Fixed in the prompts: foreground only, commit and push after each step.
3. **Owner checks on the critical path:** E9 part 2 and E10 waited for in-game answers (Q7); planned, not waste.
4. **Release scope churn:** three runs for one release (#106), because releases were planned before the items in them
   had merged.

## One rule that changes

A cause that repeated and is not fixed at its source yet: **deliverables missing at merge**, four times (#97 and #124
no screenshots, #102 no 360 px shot, #117 built only part of its plan). Each needed a follow-up or went out without
the evidence. The other repeats are already fixed at their source: runs ending early (foreground + push after each
step), routing (#71's Sonnet guard; each plan names its model), PR opening (#125).

**New rule (from 0.4 on):** every issue's *Acceptance* list is the review checklist. The reviewer answers each line
with pass / fail and the evidence (test name, file, screenshot path); one missing line is `VERDICT: CHANGES`. Every
0.4 plan file (`docs/plans/0.4/`) is written that way.
