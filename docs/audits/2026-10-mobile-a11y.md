# Mobile & accessibility audit — 2026-10-13

One-off audit (Product Design / QA). Build: `fix/icon-names` (= v0.1.5 + icon file names). **Line numbers refer to the
pre-0.2 single file `src/index.html` at commit 0976ffa**; since 0.2 step 2 the CSS lives in `src/styles/app.css` and
the script in `src/main.js` (same content, same order). Screenshots and raw results stayed in the audit workspace.

**Method:** 390×844 (main), 375×667 and 430×932 spot checks, 1500×1000; DPR 2 + touch emulation; 320 px reflow; 640 /
260 / 195 px (page zoom 200 % / 150 % / 200 % on iPhone); landscape 844×390; WCAG 1.4.12 text spacing. States: fresh
save (Lv 1 and default), the user fixture at Lv 27, Lv 45 end state; Basic and Advanced. axe-core on 20 combinations,
target-size / overflow / small-text probes, Tab walk with focus-ring detection, ARIA snapshots, reduced motion, touch-drag
simulation. **Not verified on a real iPhone**: items marked *(iOS, inferred)* are known WebKit behaviour.

**Summary:** technically sound — no horizontal overflow from 320 to 1500 px, zoom not blocked, every form control named,
menus return focus, focus rings almost everywhere; axe finds only contrast, landmark-unique, scrollable-region-focusable
and one label mismatch. The real problems are phone layout and touch ergonomics. Desktop is in good shape.

## P3 · nice to have

1. Minimum text on touch: 11 px for mono capitals, 12 px otherwise (`.sd-tab`, `.nsinfo`, `.run-tag`, `.gate .num small`,
   `.q-inl`, `.ms-meta`, `.modeseg` are 8.5–10.5 px).
2. Cleared steps keep long struck-through paragraphs in a ~190 px column on phones: clamp them.
3. Meaning only in `title` tooltips (touch users never see them), e.g. the two-tap Sealed Dungeon checkbox (l. 2282).
4. Nothing announces Level up / Next up changes to screen readers: create `#rwToast` (l. 2428) at load as a live region.
5. `#spSoon`, `#dvThen`, `#stSoon` are scroll regions keyboard users can't focus.
6. The toast's Undo is 12 px and disappears after 6 s (WCAG 2.2.1).
7. `background-attachment: fixed` (l. 68) → a fixed pseudo-element.
8. Overall progress % not exposed to screen readers.
9. Milestone `h3`s inside `<summary>` may be skipped by VoiceOver's heading rotor (verify on a device).

## PWA / store notes

- *(inferred)* Safari deletes script-written storage after 7 days of Safari use without a visit, unless the site is on
  the Home Screen; `persist()` doesn't guarantee otherwise → Add-to-Home-Screen hint + export nudge (planned), sync code
  (0.5).
- Manifest: "any maskable" on the same PNGs; no screenshots; 192 px touch icon where iOS wants 180×180.
- No `viewport-fit=cover` / safe-area insets (matters for an edge-to-edge build: Build tab l. 478, toast l. 945).
- `100vh` → `dvh`. Pop-out correctly hidden on phones (no Document PiP); a phone build would want a compact Next up view.
- The level-up chime (Web Audio) may ignore the iPhone silent switch: a visible sound toggle (`state.sound` exists).
