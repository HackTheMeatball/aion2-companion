# 0.2.5 save safety (design)

Status: **proposal for owner approval** (visible change; mockup first, ROADMAP 0.2.5). Inputs: ROADMAP ("Save safety"),
docs/team/HANDOFF.md "Waiting on the owner" (timestamp as an optional field in the existing save; one nudge after 14 days;
hint once on iPhone), docs/ARCHITECTURE.md (storage key, migrations), CLAUDE.md "Never break saved progress".

Docs only: `src/` is untouched. Mockup: `docs/design/mockups/0.2.5-save-safety.html`; screenshots (390 / 1280 px, light /
dark): `docs/design/mockups/0.2.5/`. Regenerate with `node docs/design/mockups/shoot-0.2.5.mjs`.

**Light screenshots:** the app has a single dark theme today (`src/styles/app.css` header). The light set uses a
provisional palette defined only inside the mockup, to check the layout and contrast of the new elements. It is not a
proposal for a light theme (that belongs to the colour sprint).

## 1. What ships

| # | Element | Where | Basic | Full |
|---|---|---|---|---|
| 1 | "Last backup" line | the existing footer export row (`#xfer`), after "Progress is saved in this browser only." | yes | yes |
| 2 | Export nudge | one slim card under the header, above the layout (same slot and layout as `#saveWarn`) | yes | yes |
| 3 | Add to Home Screen hint | the same card slot as 2 | yes | yes |

No new card type, no new section, no extra row in the rail. The nudge and the hint reuse one card layout
(`.card.nudge`: one row, text left, buttons right, wraps on phones). Basic mode shows them: they protect the save, and
Basic hides other chrome, not this. The footer is not hidden in Basic today, so the line shows there too.

Only one of 2 and 3 is ever on screen. If both would show, the nudge wins and the hint waits for a later visit.

## 2. Wording (exact)

Line (element 1), in `.xfer`, class `backup-line`:

- never exported: `No backup yet.`
- under 1 day: `Last backup: today.`
- 1 day: `Last backup: yesterday.`
- 2 or more days: `Last backup: N days ago.`
- 14 days or more: same text, class `stale` (amber text, same as other `--warn` text; no icon, no bold)

Days are whole calendar days in the browser's time zone, computed at render. No "hours", no weeks or months (one
unit keeps it short and testable). If the clock is wrong (timestamp in the future), show `Last backup: today.`

Nudge (element 2): `You haven't exported a backup in N days. Progress lives in this browser only.` with buttons
`Export progress` and `Not now`. When never exported and the baseline (§3) is 14 days old, the text is
`You haven't exported a backup yet. Progress lives in this browser only.`

Home Screen hint (element 3): `Safari can clear a site's saved data after a week unused. To keep your progress, export
it, then tap Share and Add to Home Screen. The Home Screen copy starts empty: import your file there.` with buttons
`Export progress` and `Got it`.

The last sentence matters: on iOS the Home Screen app has its own storage, so it does not see the Safari tab's progress.
Telling the player to add it without that sentence would look like data loss.

**To verify before build (owner or a permitted source):** the "after a week unused" claim and the "Home Screen app
keeps data longer" premise come from the ROADMAP note, not from a source recorded in `claims.json`. Per the data policy
it is single source until checked; reword to "Safari can clear a site's saved data" (no number) if it is not confirmed.

## 3. When it shows and hides

**Export button available** means the same condition as `#expBtn` today (standalone site always; claude.ai only when the
downloads permission is granted). Elements 1 and 2 need it, since both point at Export.

Element 1 (line): shown whenever `#expBtn` is visible. Updates after an export without a reload.

Element 2 (nudge) shows when all of these hold:

1. `#expBtn` is available, and the save-failed banner is not showing (that banner already says "Export a backup").
2. The player has progress worth saving: at least one tick (`Object.values(checks).some(Boolean)`) or level above the
   default of 5.
3. `now - base >= 14 days`, where `base` = `backup.lastExportAt`, else `backup.since` (§4).
4. `now - backup.nudgeAt >= 14 days` (or `nudgeAt` absent).

It hides on: a successful export (the line updates, the card goes), `Not now` (sets `nudgeAt = now`; it returns only
after another 14 days without an export), and while the save-failed banner shows.

"One nudge" is read as: never more than one at a time, and never more often than once per 14 days. It does not
come back every visit and it never blocks anything.

Element 3 (hint) shows when all of these hold:

1. iPhone Safari, not already installed: UA contains `iPhone` (and `iPod`), is not Chrome / Firefox / Edge on iOS
   (`CriOS`, `FxiOS`, `EdgiOS`), and `navigator.standalone` is not true. iPad is out of scope (ROADMAP says iPhone).
2. Standalone site only: never in the claude.ai build (`window.claude` present, ROADMAP) and never in
   `dist-artifact`.
3. The player has progress worth saving (same test as 2.2).
4. `backup.a2hsAt` is absent, and no nudge is showing.

It hides on: `Got it` (sets `a2hsAt = now`, never shown again), `Export progress` (exports, then keeps the card until
`Got it`, since the Share step comes next), and when the page is opened from the Home Screen
(`navigator.standalone`). A player who already added it never sees it, and the hint never re-arms.

Open question for the owner: should the "last backup" line also hide in the claude.ai build, like the hint? The
mockup assumes it follows the export button (it shows when export works there), since artifact storage can be lost too.

## 4. Storage

One optional object on the existing save, no new key:

```json
"backup": { "lastExportAt": 1760000000000, "since": 1759500000000, "nudgeAt": 0, "a2hsAt": 0 }
```

- All fields are epoch ms numbers, all optional. Absent or not a finite positive number = "never".
- Key stays `aion2-assassin-route-v4`; no rename, no version, no second key (CLAUDE.md).
- Written through `storeState()` like everything else. It goes in the top level of the save, not per character, since
  it describes the browser copy. It is not synced: unknown top-level fields stay local in `merge()`
  (`src/core/sync.js`), so a later cloud sync neither carries nor clobbers it.
- `lastExportAt` is set when the export is handed to the browser (Blob path: on click; claude.ai path: after
  `dl.save` resolves, not on `declined` or an error). The browser gives no confirmation that the file was kept, so the
  line says "Last backup", not "saved". The exported file is written before the field is updated, so a file never
  contains its own timestamp; this is fine.
- `since` is the baseline for players who never exported, so "14 days" has a start: set once by the new
  migration (below) to the load time. It is never moved by later writes, and it is ignored once `lastExportAt` exists.
- Import: the file replaces the save. If the file has no `backup` object, import sets `backup.since = now` so the
  nudge does not fire the instant after a restore. A file that carries `backup` keeps it.

Migration (additive, once, idempotent, leaves old data in place): flag `backup1` in `src/core/migrations.js`, run
after the existing steps. If `hadSave` and `backup` is not an object, set `backup = { since: now }`. Set the flag.
Never delete or change any other field. It must not run for imported files that already set the flag, and an older
build that loads the save ignores `backup` (unknown fields are kept, as for `savedAt`). The import path adds
`backup1: true` to the file like it does for the other one-time flags.

`now` here is the clock value the migration is given (seconds, like the other steps); store ms in the field so it
matches `savedAt`.

## 5. Accessibility

- The nudge and hint are `role="status"` (polite), not `role="alert"`: they are advice, unlike the save-failed banner.
  They are inserted hidden-then-shown by toggling `hidden` on a container that is always in the DOM, so screen readers
  announce the change.
- Focus is never moved to them. They come right after the header in reading order so keyboard users reach them early.
- Buttons are real `<button type="button">`, 12 px mono like `.xfer-btn`; on touch they get the 44 px target size the
  rest of the page uses (0.1.9). `Not now` and `Got it` have `aria-label`s that name what is dismissed.
- Colour is never the only signal: the stale line differs from the normal one by its text (the number of days), not
  only by amber. Amber on the dark panel is `--warn` text already used elsewhere (contrast checked by the `a11y`
  suite); the light mockup palette uses a darker amber for the same reason.
- The line has no live region (it changes only after the player's own click, and `#xferMsg` already announces export
  results). Text wraps at 390 px and at 200% zoom with no horizontal scroll (see the 390 px screenshots).
- `prefers-reduced-motion`: no animation anywhere.

## 6. Tests to add

Node (`tests/core/`, no browser, `node tests/core.mjs`):

1. `migrations`: `backup1` is additive (only `backup` and the flag are new; deep-equal of the rest), idempotent
   (second run no change), writes only when `hadSave`, leaves an existing `backup` untouched, and ignores a malformed
   `backup` value (string, array, negative numbers) without throwing.
2. `sync`: `merge()` keeps the local `backup` and never copies the remote one; `syncedPart` excludes it.
3. A pure helper (new, in `src/core/`, e.g. `backup.js`, no DOM, takes `now` and the save): `backupLine(save, now)`,
   `shouldNudge(save, now, canExport, saveFailed)`, `shouldHint(save, now, env)`. Table tests: never / 0 / 1 / 2 / 13 /
   14 / 15 days; future timestamp; `nudgeAt` within and past 14 days; no progress; `since` only; claude.ai env; each
   iOS UA (Safari, Chrome iOS, iPad, standalone).
4. A source rule: `core/` stays free of DOM and storage (existing rule) for the new file.

Browser (`site` and `e2`/`a11y` suites):

5. `site`: after Export, `backup.lastExportAt` is set, the line reads `Last backup: today.`, and the storage key is
   still `aion2-assassin-route-v4` with no other new key; the exported file has no `backup.lastExportAt` of its own.
6. `site`: a save with `lastExportAt` 15 days ago shows the nudge in full and Basic mode; `Not now` hides it and it
   does not return after reload; clicking Export hides it.
7. `site`: with an iPhone Safari UA (Playwright `userAgent`), the hint shows once; `Got it` persists across reload; it is
   absent with a desktop UA, a `CriOS` UA, `navigator.standalone = true`, and in `dist-artifact`.
8. `a11y`: the nudge and hint have `role="status"`, buttons have names, no contrast failures in either state.
9. `e2-migtest`: an old save loads in the new build with every key intact and `backup.since` added, and the save the new
   build wrote loads back in the previous build (as the existing migration tests do).
10. Per CLAUDE.md, run `mig1`, `mig2` and `journey` when building this, and update golden snapshots only if a visible
    change is intended and explained in the commit.

## 7. Out of scope

Automatic downloads, cloud backup (0.6 sync), reminders by e-mail or notification, an Android install prompt, anything
about iPad, a light theme, and any wording for other languages.
