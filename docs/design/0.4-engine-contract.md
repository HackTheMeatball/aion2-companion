# 0.4 engine contract: pack code, hooks, card registry, term list

0.4 P0 (#139), docs only. The spec P2b, P2c, P4a–P4c and P5a–P5d build from, and the term list P8 scans for. Read with
docs/ARCHITECTURE.md, ROADMAP.md "0.4" and docs/audits/2026-10-16-audit-and-plan-to-1.0.md. Line numbers are at
`7d17146` (main after P3a). Where this doc changes a plan file in `docs/plans/0.4/`, that file was edited in the same PR
(listed in §7).

Words used here: **engine** = `src/core/` + `src/cards/` (no game term); **shell** = `src/main.js` + `src/shell/`;
**pack** = a game's code under `src/packs/<game>/` (data stays in `data/packs/**`, P1).

## 1. Code layout and the import rule

| Folder | What | Imports allowed |
|---|---|---|
| `src/core/` | engine: state, save, storage interface, evaluator glue, requirements, Next up ranking, card registry, the pack holder (`pack.js`) | `src/core/` only |
| `src/cards/` | engine cards: Next up, Later, milestones, Route rules, Journey, Sources, Confidence, Undo (P4a, P4c) | `src/core/`, `src/cards/` |
| `src/shell/` | web platform glue: the `localStorage` adapter (P3b), service worker registration when it leaves `site.js` | `src/core/`, `src/shell/` |
| `src/packs/aion2/` | the AION 2 pack's code: `pack.js` (the pack object), `data/` (today's `src/data/*.js` and the compiled modules), `catalog.js`, `rules.js` (kept rules, switch table, graph transforms), `requirements.js` (regional / skill / board / stigma / area / rotation helpers), `load.js`, `nextup.js` (producers), `ascension.js`, `cards/` (its cards and their markup) | engine, `src/packs/aion2/` |
| `src/main.js` | the page shell: imports one pack, hands it to the engine (`usePack`), registers cards, load / save, layout fitting, header, export / import, *Report a problem* | everything |
| `src/site.js`, `src/sw.js` | unchanged (web only; `sw.js` keeps its `aion2-route-*` cache names, P3c no-go) | as today |

The rule: `src/core/` never imports `src/packs/`, `src/cards/`, `src/shell/`, `src/data/` or `src/main.js`; `src/cards/`
imports only `src/core/` and `src/cards/`; a pack imports the engine and itself, never another pack; nothing in the
engine imports a pack. The engine reaches pack data and code only through the pack object (§2).

**Enforced by** `tests/core/purity.test.mjs` (extended in P2b, which creates `src/packs/`): one test per row above,
reading every `import … from "…"` of every file and resolving the path; each test has a negative control in its PR (a
planted import fails it). Until P2b, `src/data/` is still allowed for `src/core/` (today's rule).

**One global scope** (ARCHITECTURE §4: esbuild, no tree shaking, every top-level name a page global). Names stay unique
this way:

- A moved name keeps its name (tests, baselines and inline `onclick` call them); it was unique before the move, and
  `scripts/build.mjs`'s duplicate-name check proves it still is. P2b extends that check from `src/{core,data}` +
  `main.js` to every `.js` file under `src/` the page bundle includes (`core`, `cards`, `shell`, `packs/**`, `main.js`).
- New engine names are neutral nouns (`definePack`, `usePack`, `activePack`, `registerCard`, `mountAll`, `updateAll`).
- New top-level names in a pack start with the pack id: `aion2Pack`, `aion2Producers`, `aion2Transforms`.
- Hooks are properties of the pack object, not globals: the engine calls `activePack().story.here(state)`, never a
  pack's global function. That is what keeps a second pack from colliding with the first (0.6 loads one pack per page).

## 2. The pack interface

`src/core/pack.js` (new in P2b):

- `definePack(spec)` → a frozen pack object. Throws on an unknown key, a missing required key or a hook of the wrong
  type, so a typo fails at load, not at the first call. Only `id`, `data` and `catalog` are required; every hook below
  has a default that means "this game has none" (P6's fake game uses only the required keys and one producer).
- `usePack(p)` sets the active pack (the shell, once, before `migrate()`; `tests/support/core-bundle.mjs` for `core`,
  `equiv`, `invariant`). `activePack()` returns it and throws if none is set.
- Engine modules call `activePack()` inside functions only, never at module top level: modules are evaluated before
  `main.js` calls `usePack`. Values built once (today's `APP_GRAPH`, `SQ_ID`) become memoised on first call, per pack.

```js
export const aion2Pack = definePack({
  id: "aion2",                       // P1's game pack id
  data: { graph, proposed, story: { quests, steps, notes } },   // GATE_GRAPH, GATE_PROPOSED, QUESTS, QUEST_STEPS, QUEST_STEP_NOTES
  catalog: { milestones, routes, rowKind, offered, promised },
  charFields, keptRules, gateChanges, graphTransforms,
  story: { levelGate, isTalkOnly, subs, here, meanwhile, cardFields },
  hopName, locate, skipLocation, onLoad,
  nextUpProducers, cards, nowRenderers, rowRenderers, rowHooks, text,
});
```

|---|---|---|---|
| `data.graph`, `data.proposed` | the compiled gate graph and proposals | `evaluate()` (its `opts.graph` default and `GATE_PROPOSED`) | required / `{}` |
| `data.story` | `{ quests: [[lv, name, …]], steps: {name: [text]}, notes }` | story position, objectives, fresh start (first quest), story-end move-on | required |
| `catalog.milestones`, `catalog.routes` | the finished `GATES` / `STEPS` (pack builds them at module load, as today) | `itemByK`, `cardRows`, counts, `openSteps`, milestone and Route cards | required |
| `catalog.rowKind(it)` | a row → `"main"` / `"side"` / `"none"` | `cardRows`, `checkableOf` and the counts: `none` = not a milestone row (board nodes, Sealed Dungeons), `side` = listed last, not in main counts (regional quests) | `"main"` |
| `catalog.offered(it, k)` | → bool | `openSteps`: may Next up offer this row (false for skill and board lines, stigma equips and "Put … on E") | `true` |
| `catalog.promised(it, k)` | → bool | Next up's laterStep (P2c): may the Later card name this row's milestone (false for skill and board lines, which have their own Buy / Later cards; stigma rows count, their milestone shows its title) | `true` |
| `charFields` | names | `CHAR_FIELDS` = engine fields (`checks`, `level`, `quest`, `storyEnd`, `qsteps`, `qsub`, `started`, `mt`) + these | `[]` |
| `keptRules` | `{ name: text }` (today's `KEPT_RULES`, verbatim) | not called; `tests/core/gate-sources.test.mjs` pins it | `{}` |
| `gateChanges` | the switch table (today's `GATE_CHANGES`, verbatim: `what`, `baseline`, `needs`, `records`, `apply`) | `setGateChanges` / `gateChangeOn` (engine) validate names against it | `{}` |
| `graphTransforms` | `[{ id, when, apply(graph) → graph }]`, `when` = `"always"` or `{ off: "<switch>" }` | building the app graph: the transforms whose `when` holds, in list order, memoised per set of switches on | `[]` |
| `story.levelGate(c)` | → `{ gated, gateLv }` | the story card (Next up) | never gated |
| `story.isTalkOnly(text)`, `story.subs(text)` | objective text → bool / sub-steps | `objIdxOf`, the Journey card's checklists | `false` / `[]` |
| `story.here(state)` | → `{ kib?, m?, zone? }` or `null` (where the story sends you) | story card, Journey card | `null` |
| `story.meanwhile(state, ctx)` | → the story card's "Meanwhile" object or `null` | story card when level-gated | `null` |
| `story.cardFields(state, { ...ctx, open })` | → fields added to the story card's objectives version (`open` = the open objective's text; AION 2: `kib`, where to go next) | story card (P2c: the field name and the "objective already names its Kibelisk" rule are the pack's) | `{}` |
| `hopName(r)` | evaluator node result → `{ name, verb }` or `null` (skip the hop) | `blockerChain` | the row's bold text via `itemByK`, verb "is done" |
| `locate(k)`, `skipLocation(k)` | save key → zone or `null`; → bool | `lastConfirmedLocation` (`src/core/sync.js`) | `null` / `false` |
| `onLoad(save, c, { fresh })` | mutates `c` in memory, never writes storage | `migrate()`, after the fresh start, before the story-end move-on (today's order) | none |
| `nextUpProducers` | `[{ id, produce(state, ctx) → [{ phase, card, keep?, queue?, L? }] }]` (below) | `rankNext`, once each per call, in list order | `[]` |
| `cards` | card specs (§4) | the shell registers them with the engine's cards | `[]` |
| `nowRenderers` | `{ kind: (card, ctx) → view }` (P5a: the view object `nowCard` lays out, html in its strings; `done` = the primary button, `queue` = only the queue's first card gets it), plus dotted hook keys: `story.meanwhile`, `story.where`, `now.act`, `now.click`, `now.toggle`, `now.docClicks`, `skill.slot`, `ahead.cap` (listed in `src/packs/aion2/cards/nextup-kinds.js`) | the Next up / Later cards for a card whose `kind` the engine doesn't draw (P5a) | none |
| `rowRenderers` | `{ kind: (row, k, ctx) → html }` (the whole `<li>`; `ctx` = `{ c, row(extra) }`, `row` = the engine's `<li>` with `extra` = `{ pre, cls, post }`: classes after the base class, classes at the end, markup after the label) | milestone and Route cards for a row whose kind it lists (`row.kind \|\| row.group`, `"item"` when it has neither; rows of `catalog.rowKind` `"none"` never reach it); else the engine row (P5b) | none |
| `rowHooks` | `{ name: fn }`: `text()` and `sync()` (every update: the shell's `fillStigmaText` / `syncQRun` calls), `ticked(k, on, was)` (a box changed, before the save and redraw), `click(e)` (capture-phase click in the milestone list), `snooze(k)`, `turnedIn(k)` (the Next up card's quest buttons) | the milestone card (`src/cards/milestones.js`); added by P5b because the pack's rows also behave, not only draw | none (a missing hook does nothing) |
| `text` | `{ key: string }` (site names, the Sources intro, game words in card labels) | engine cards, for words they may not hold (P5d) | `{}` |

**Switches.** The engine owns the mechanism (`setGateChanges`, `gateChangeOn`, `CHANGES_ON`, the memoised graph per
set). It reads five switch names itself, each about engine behaviour: `derived` and `followUps` (evaluator options),
`turnInLevel`, `blockerText`, `stepNotes`. A name the pack doesn't declare reads as on, so a pack with no table gets
today's behaviour. Every other switch (`regionalTurnedIn`, `storyStepDerived`, `clearTally`, the five E5 gates,
`ascensionBar`, `specialtySlots`) is read by pack code only. `golden --explain` and `equiv` keep working unchanged.

**The graph.** `appGraph()` today is APP_GRAPH (kept rules) → `APP_GRAPH_0_2` (regionalTurnedIn off) →
`withoutStoryStep` → `withoutE5` → `withoutSlots`. As transforms, in this order: `stronghold-band`, `slot1-after-g22:0`,
`skill-line-level` (the `get req()` getters; `when: "always"`), `regional-0.2` (off: `regionalTurnedIn`), `story-step`
(off: `storyStepDerived`), one per E5 switch (off: that switch; their record sets don't overlap, so one at a time equals
`withoutE5`), `specialty-slots` (off: `specialtySlots`). P2b proves equality with `equiv` and golden, no re-record.

**Next up phases** (P2c). Producers return entries; the engine sorts by phase, then by producer list order, then by
the order each producer returned. The card objects stay exactly what they are today; `phase`, `keep`, `queue` and `L`
live on the entry, so nothing a test or `nowCard` reads changes.

| Phase | Today (in `rankNext` order) | Who |
|---|---|---|
| `spend` | run (dungeon in progress), cube, skill (+ queued previews), board / boardcost, stequip / stup | pack |
| `here` | steps of the milestone you stand on (`openSteps`, not side, not advice) | engine |
| `beforeStory` | rq card (when `ctx.story.gated` and it has open quests), sd card (when gated) | pack |
| `missed` | up to 2 missed steps | engine |
| `story` | the story card | engine (`levelGate`, `here`, `meanwhile` from the pack) |
| `side` | rq card (otherwise), sd card (not gated), stwait | pack |
| `advice` | advice steps (Advanced) | engine |
| `late` | sh card | pack |
| `later` | laterSkill (pack) and laterStep (engine), merged and sorted by `L` | both |

`ctx` = `{ c, lv, ev, basic, story: { qi, gated, gateLv }, here }` (`here` = the milestone you stand on). `keep: true`
= always shown past the 8-card cap (today rq, sd, sh, stwait); `queue: "skill"` = Basic shows only the first card of the
queue (today's `act === "skill" && i !== fs0`). The Basic filter (`later`, `adv`, queues) and the cap stay in the engine.

## 4. Card registry interface (P4a)

`src/core/cards.js`, pure (no DOM: the shell resolves elements and passes them in).

```js
registerCard({
  id: "sources",            // unique; the registry rejects a second registration
  slot: "foot",             // a page slot, or "<cardId>.<section>" for a section of another card
  order: 300,               // unique within the slot; mount and update run in ascending order
  root: "srcCard",          // DOM id of the card's outer element (the shell looks it up)
  sections: [],             // section names other cards may fill ("after-timeline")
  mount(el, ctx) {},        // once, from render(); optional
  update(ctx) {},           // every update(); optional (null = mount only)
});
```

- **Slots** (the containers in `src/index.html`): `rail` (`aside.rail`), `top` (`.top-grid`), `main` (`main`, after
  the top grid), `foot` (`footer.foot`), `drawer` (`aside.statdrawer`). An unknown slot, a duplicate id, a duplicate
  `order` in a slot or a section slot whose card doesn't declare that section throws at registration (P4a's test).
- **Order rule:** `order` decides call order, not DOM position (the markup's place in `src/index.html` does). Orders
  go in steps of 100 per slot, so a card can be put between two without renumbering. `mountAll` and `updateAll` walk the
  slots in the order listed above, and cards in ascending `order` within each slot; a card's sections run right after
  the card. P4a writes the table of order values in ARCHITECTURE §2, chosen so the calls happen in today's `updatePass`
  sequence (milestones and Route counts → areas → Skills (`renderNext`) → Cube → Stigmas → `fillStigmaText` →
  `syncQRun` → Next up); the DOM snapshot and golden prove it.
- **`render()` and `update()`:** `render()` builds what isn't a card yet, then `mountAll(els, ctx)`. `update()` keeps
  `gatesPass` around everything; inside it the shell's own work runs first, then `updateAll(ctx)`. While cards move
  (P4a–P4c) a moved card is called with `updateCard(id, ctx)` at the exact spot its old call stood; once P4c lands,
  `update()` is the shell's work plus one `updateAll(ctx)`.
- **Calls between cards:** a verbatim-moved card that calls another card's render (today `renderNext` calls
  `renderQuest`, `renderAscension`, `renderDaevanion`, …) keeps the call. The called card registers with `update: null`
  so it isn't drawn twice; the call leaves when a feature touches the caller, not in 0.4.
- **`ctx`** = `{ state, c: char(state), pack: activePack(), basic: state.mode === "basic", ev }`, built once per
  `update()`; `ev` is a getter for `gatesOf(c)` (memoised by `gatesPass`). A card reads nothing else from the shell.
- **Who registers:** card modules export their spec and never call `registerCard` at import time. `main.js` registers
  the engine cards and every spec in `activePack().cards`. Per-pack loading (0.6) then only changes which pack is
  imported.
- **Static markup leaves `src/index.html` with the DOM byte-identical:** each card's markup moves verbatim into its
  own file (`src/cards/<id>.html`, `src/packs/aion2/cards/<id>.html`), and the shell keeps one line
  `<!-- @card cards/sources.html -->` where it stood. `scripts/build.mjs` replaces that line with the file before
  inlining (both builds, so `dist-artifact` stays one file), and fails on a missing file or a leftover `@card` line.
  Rejected: inserting markup from JS at load (needs a placeholder node, changes first paint and the DOM before
  `render()`). P4a's `tests/support/dom-snapshot.mjs` proves each move.

## 8. Findings: generator checks (P6a, #179)

## 9. Findings: the fake game (P6, #154)

P6 runs the engine on a game that isn't AION 2: `tests/fixtures/packs/fakegame/` (a game pack and a guide pack, 27 lines
of records) and `tests/core/conformance.test.mjs` (both chains: generator, fresh save, Next up, save / reload / merge, the
